### Implemented behavior

- The runner validates the complete ledger first. A gate pin carries `scope: gate` and exactly the tree hash for MVTec and config and manifest hashes for both gate configs. It permits assigned gate execution and joint gate approval. Full-study pinning verifies all active datasets and configs. Both pin files are write-once.
- `--prepare --queue` verifies each selected config owned by the member against the shared pin. The per-owner readiness file at `artifacts/distributed/ready-<owner>.json` records the verified configs, pin digest, plan digest, hardware fingerprint, review and durable bundle prefix. Each preparation replaces that member's local readiness file. Repeat preparation when switching queues, pins or sessions. A gate-only pin requires an explicit gate queue. Execution rechecks source, readiness coverage and input bytes, and fit/evaluation rebuild the pinned manifest.
- Existing full v1 pins and full-owner commands remain supported. A legacy unversioned readiness file is valid only against its matching full pin and environment. Result identity still depends on the source, owner/job/profile, resolved config, dataset, split, seeds and canonical paths. The pin's scope does not enter that identity. Existing publication and conflict checks protect the results and bundles.
